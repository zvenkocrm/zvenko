# Участие в разработке

## Окружение

1. Поставьте [mise](https://mise.jdx.dev) и Docker.
2. `mise install` — Node.js, pnpm, gitleaks, lefthook, OpenTofu, osv-scanner. Версии закреплены в `mise.toml`.
3. `pnpm install`.
4. `pnpm dev:up` — локальные сервисы и git-хуки. Пароли для разработки генерируются в `.env` (не коммитится).

Есть только Docker? Подойдёт Dev Container — появится вместе с первыми приложениями.

**Безопасность установки зависимостей** (`pnpm-workspace.yaml`):

- новые версии пакетов ставятся только через 24 часа после публикации;
- при снижении уровня доверия к пакету установка падает;
- скрипты установки разрешаются явно, по одному пакету.

**Телеметрия Turborepo:** отключите локально командой `pnpm exec turbo telemetry disable`. В CI она отключена.

## Как вносим изменения

**Ветки:** `main` защищена и меняется только через PR. Имена веток — `<тип>/<кратко>`, например `feat/deals-kanban`, `fix/webhook-signature`.

**Коммиты** — [Conventional Commits](https://www.conventionalcommits.org/ru/), описание по-русски:

```
feat(crm): канбан сделок
fix(channels): проверка подписи вебхука Telegram
```

Один коммит — одно логическое изменение. Сообщение проверяет commitlint в git-хуке.

**Git-хуки (lefthook)** перед коммитом проверяют секреты (gitleaks), формат и линт; перед push — типы. Хуки — удобство: всё то же самое проверяет CI.

## Когда изменение «готово»

- [ ] Код и тесты; в описании PR — ID требований.
- [ ] Формат, линт, типы, тесты, сканеры безопасности — зелёные.
- [ ] Новые эндпоинты — с тестом изоляции компаний. Новые таблицы — с `tenant_id` и политиками RLS.
- [ ] Бюджеты скорости не просели.
- [ ] Нет секретов. Для новой зависимости объяснено, зачем она и почему ей можно доверять.
- [ ] Документация и changelog обновлены.
