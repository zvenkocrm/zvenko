# Проверка безопасности перед PR

Прогони проверки по порядку. Не останавливайся на первой ошибке — собери все находки и выдай одним списком.

## 1. Автоматические проверки

Инструменты — из `mise.toml`. Если команда не находится, сначала выполни `mise install`.

```sh
gitleaks git --redact --no-banner                       # секреты во всей истории
osv-scanner scan source --lockfile pnpm-lock.yaml       # уязвимые зависимости
pnpm format:check && pnpm lint && pnpm typecheck && pnpm test
```

## 2. Ручной просмотр изменений

Посмотри `git diff main...HEAD` и проверь по [CLAUDE.md](../../../CLAUDE.md):

- **Новая таблица с данными компании:**
  - есть `tenant_id`;
  - RLS `ENABLE` + `FORCE`;
  - политика изоляции `AS RESTRICTIVE`;
  - без контекста запрос возвращает 0 строк.
- **Новый эндпоинт:** есть тест «компания A не видит и не меняет данные B»; чужой объект → 404.
- **SQL** — только параметризованный, без склейки строк.
- **Внешний вызов:**
  - через адаптер;
  - таймаут и повтор;
  - нет персональных данных во внешних API за пределами РФ;
  - для URL от пользователя — защита от SSRF.
- **Новая зависимость:** зачем она нужна, сколько у неё загрузок и мейнтейнеров, нужны ли ей скрипты установки (`allowBuilds`). Чем меньше зависимостей, тем лучше.
- **Логи:** нет телефонов, почт и текстов сообщений.
- **Публичный репозиторий:** нет данных клиентов, сведений о пилотах, бизнес-документов.

## 3. Отчёт

Выдай пользователю:

- что проверено;
- что найдено — с файлом и строкой;
- что исправить до PR.

Ложное срабатывание gitleaks не отключай правилом: только `gitleaks:allow` на конкретной строке с пояснением.
