# Звенко — правила разработки

Публичный репозиторий продукта (лицензия FSL). Внутренние документы компании — исследования, требования, ADR, бизнес-план — живут в отдельном приватном репозитории.

## Нельзя

- **Коммитить секреты, данные клиентов, сведения о пилотных клиентах и бизнес-документы.** Репозиторий публичный.
- **Писать SQL склейкой строк** — только параметризованные запросы.
- **Добавлять таблицу с данными компании без `tenant_id`, RLS (`ENABLE` + `FORCE`) и ограничивающей политики изоляции (`AS RESTRICTIVE`).** Обычные политики PostgreSQL объединяются через ИЛИ.
- **Добавлять эндпоинт без теста изоляции компаний** «A не видит и не меняет данные B». Каждый адрес — в реестре `apps/api/test/isolation.test.ts`, иначе тест упадёт.
- **Читать и менять данные компании в обход `TenantDb`** (транзакция с профилем доступа) и ставить `@Public()` без необходимости.
- **Обращаться к таблицам чужого модуля напрямую** — только через публичный интерфейс модуля.
- **Трогать схему `identity` (пароли, сессии, токены) не из модуля входа** и выдавать роли приложения права на неё. Новые эндпоинты Better Auth — только осознанно: лишние выключены в `disabledPaths`.
- **Менять и удалять записи журнала аудита** — он только дописывается. Важные действия пишутся через `AuditService` в транзакции действия (CONTRIBUTING.md, «Журнал аудита»).
- **Импортировать `drizzle-orm` в приложениях напрямую** — только из `@zvenko/db`, иначе две копии библиотеки дадут несовместимые типы.
- **Отправлять персональные данные во внешние API за пределами РФ.**

## Нужно

- **Строгий TypeScript.** Проверки с учётом типов в ESLint — ошибки, а не предупреждения.
- **Тесты:** юнит (Vitest), интеграция с настоящим PostgreSQL (Testcontainers), e2e (Playwright) — для критичных сценариев.
- **Внешние сервисы** (облако, ИИ, каналы, платежи) — за адаптером с контрактными тестами.
- **Коммиты** — Conventional Commits, описание по-русски; один коммит — одно логическое изменение. `main` — только через PR.
- **Перед коммитом** — `pnpm format:check && pnpm lint && pnpm typecheck && pnpm test`.

## Инструменты

Версии закреплены в `mise.toml`, команды проекта — в `package.json`. Локальная среда — `pnpm dev:up`, API — `pnpm dev:api`.
